  What the generator renders, from public data only:
    - npm downloads over the last 12 months (and the last 30 days). The package
      list is discovered at run time from the npm registry search
      (maintainer:m_guttmann), so a newly published package counts without a
      code change. A package is named and linked only when its GitHub repository
      is verified public at render time (found by an is:public repository
      search); all others count towards the total, unnamed, and the block
      states no reason per package.
    - Upstream repositories the owner does not own. Forks are excluded, and a
      pull request counts as merged only when someone other than the owner
      merged it. Per repository: the count, the three newest merged pull
      requests and a link to the full list. The block has a bounded length (at
      most three titles plus the link per repository, and a capped number of
      repositories): a further merge into a repository that already shows
      three titles only raises its count, while a merge into one with fewer
      titles adds a title line, and a first merge into a new repository adds
      its block until the cap is reached.
    - At most three open items, each with a date (never a distance), and who
      closed the closed opencode pull requests.
  Fail-closed, with two error classes. On a failure of the outside world
  (network, timeout, HTTP 429/5xx after retries, a malformed payload) the STORY
  block stays byte-for-byte as it was and the FRESH stamp reports the degraded
  run instead. A fatal error (no token, broken markers, a privacy guard
  violation, an HTTP 4xx from GitHub) writes nothing at all: STORY and FRESH
  both stay unchanged and the job goes red.
  The FRESH stamp carries the minute of the run, so every run that is not fatal
